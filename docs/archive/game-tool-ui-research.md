# ゲーム支援ツール UI調査

調査日: 2026-08-24  
対象: FGO Labのホーム、全体ナビゲーション、計算ワークスペースへ転用できる視覚設計

## 評価基準

- キャラクターやゲームデータを使いながら、主操作を見失わないか
- 計算、所持管理、育成計画を往復しやすいか
- 小さなDB画像だけでも成立するか
- SVGアイコンや大判イラストへ依存しない形へ翻訳できるか
- 均等なカード型ダッシュボードになっていないか

## FGO Labへ採用する視覚方針

### 1. グラフィカルさの作り方

大判のキャラクター画像やSVG装飾ではなく、次の組み合わせで作る。

- 濃紺の基礎面と、白に近い主要操作面
- 選択中サーヴァントの顔画像を48〜64pxで一度だけ使用
- 支援役、スキル、礼装は24〜36pxのDB画像で条件の構成を見せる
- クラス、宝具カード、適用状態に由来する限定的な識別色
- 罫線、交互背景、数値の桁揃え
- 一画面につき一つだけ、面積の大きな主操作

### 2. ホームA案の再構成

「FGOのターミナル構造」と「Fribbelsの作業面」を組み合わせる。

1. 前回の計算を、顔画像、礼装、支援役、平均ダメージを含む一つの作業スロットとして表示する。
2. 「前回を開く」を唯一の強い操作にする。
3. 新規計算、所持・育成管理、育成計画、火力ランキングは細いコマンド列にする。
4. お気に入りサーヴァントは下部プロフィール帯へ48px程度で表示する。
5. DB更新、自動保存、データ版は上部ステータスへ静かに置く。

最近使った計算を複数並べる場合も、すべてを同じ強さにしない。直近一件だけに条件画像と結果を表示し、二件目以降は名称と時刻だけの履歴にする。

### 3. 初回セットアップ

初回セットアップはFribbelsの通常ナビゲーションではなく、ChaldeaとKroosterの初回入口に近い独立画面とする。ただしアカウント登録は要求しない。

- セットアップ以外のナビゲーションを表示しない
- 現在の処理工程と失敗時の回復操作だけを表示する
- 完了後に通常ホームへ自動遷移する
- データ取得前にホームの空状態を見せない

## 比較デモへ反映した案

- A: ターミナル型。最近使った計算条件とコマンド列を左右へ分ける。
- B: Paimon.moeを参考にしたモジュラーホーム型。前回の計算を8/12幅のPrimaryとし、所持状況、育成計画、火力ランキング、新規計算を異なる面積で配置する。

Bのマイルーム型は比較対象から外した。お気に入りサーヴァント表示は、画像を拡大せず所持状況モジュール内の42px画像として残す。
