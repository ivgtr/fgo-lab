## 画面の目的

ダメージ計算と将来の編成で使う概念礼装だけを、物理コピー単位で登録・更新する。全概念礼装を未所持状態で並べて所有率を埋める画面にはしない。

## 採用した情報構造

- 初期状態は空の登録一覧とし、DB検索から使う礼装を追加する。
- 同一礼装も一枚ずつ独立した行へ表示し、礼装単位にまとめない。
- 同一礼装は初期並びで隣接させる。
- 完全に同じ限界突破段階とレベルが複数ある場合だけ、補助的に `1枚目`、`2枚目` と表示する。
- 各コピーは内部IDを持ち、個別にレベル・限界突破段階を変更、登録解除できる。
- 一覧は検索、確認、選択だけを担当し、編集はPCの右詳細またはSPの詳細画面で行う。

## 入力と保存

- 登録時は未解放・Lv.1を初期値とする。
- 限界突破段階は固定選択、レベルは直接入力とする。
- `Lv.1` と現在の限界突破段階に応じた `現在上限` をショートカットにする。
- ATKはDB値とレベルから導出し、直接入力させない。
- 妥当な変更は都度自動保存し、明示的な保存ボタンを置かない。
- 登録解除はUndo可能にする。

## ダメージ計算との契約

- 登録済み礼装は物理コピー単位で選択する。
- 全礼装から選んだ仮想状態は、利用者が明示しない限り所持データへ保存しない。
- 将来の編成ではコピーIDを使い、同一コピーの重複装備を防止できるようにする。

## 今回扱わないこと

- 全礼装の所有率管理
- 礼装効果全文の一覧表示
- 概念礼装EXP、投入素材、必要QPを使った育成目標
- 物理コピーを礼装単位にまとめた数量入力
