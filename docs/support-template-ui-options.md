# 支援条件テンプレート UI比較

更新日: 2026-08-24  
状態: 方向性確定・細部は実装時に調整  
参照デモ: `docs/support-template-ui-comparison.html`

## 画面の目的

ダメージ計算と火力ランキングへ再利用する支援条件を、DB上のサーヴァント・スキル・スキルレベルを参照して保存、編集する。FGOのパーティ配置を再現する編成画面にはしない。

## 比較する情報構造

### A. テンプレート一覧＋編集

保存済みテンプレートを左から選び、右側で支援元と使用スキルを編集する。再利用と管理に最も強い。

### B. 支援元スタック

支援サーヴァントを追加し、その配下へ使用スキルを縦に積む。新規作成に最も強いが、保存済みテンプレートの一覧性はAより弱い。

### C. 効果別台帳

最終的なバフ種類と合計から支援元を確認する。監査には強いが、一つのスキルが複数の効果行へ分散するため、主要編集画面には向きにくい。

## 全案で固定すること

- 計算済みのバフ値だけでなく、サーヴァントID、スキルID、スキルレベル、マスターデータ版を保存する。
- 支援サーヴァントは所持・育成管理と全サーヴァントのどちらからも追加できる。
- スキル名、画像、効果説明はDBを参照する。
- テンプレートは編成位置、礼装、Wave進行を持たない。
- ダメージ計算へ適用後の追加、変更、削除予定は保存内容との差分として全件表示する。
- 妥当な変更は自動保存し、明示的な保存ボタンを置かない。新規作成を既存テンプレートへ上書きする場合だけ意思確認する。

## 実装時に調整すること

1. Bの支援元スタックを基本画面として使う。
2. Cは独立画面にせず、Bの「適用効果の概要／内訳」へ統合する。
3. テンプレート名を最初に入力するか、支援元を追加した後で保存時に入力するかは、実装時の入力テストで決める。
4. 同一サーヴァントを複数追加した場合の補助表示は、実データと読み上げを確認して決める。

## 現在の有力案

Bの支援元スタックを主案とする。保存済み条件の呼び出しはセレクトボックスではなく、名前・構成要約・最終使用時刻を検索できるモーダルにする。選択肢が増えても一覧性を保ち、呼び出す前に内容を判別できることを優先する。

リッチさは装飾ではなく、次のDB情報と操作で作る。

- 支援元ごとに顔画像、自前／フレンド、DB参照状態を表示する。
- DB上の各スキルを画像、適用対象、主要効果、条件・デメリット、レベルとともに表示する。
- スキルを削除せず `使用中／未使用` で切り替え、支援元の文脈を保つ。
- 右側に支援元数、使用スキル数、効果種類別の合計を表示し、効果別内訳へ移動できる。
- 呼び出しモーダルにはサーヴァント画像、主要効果タグ、構成件数、最終使用時刻を表示する。

## 共通呼び出しUI

同じ呼び出しモーダルを支援条件管理とダメージ計算の両方で使う。検索対象、行の情報順、顔画像、主要効果タグ、構成件数、最終使用時刻を共通コンポーネントにする。

支援条件管理では選択したテンプレートを編集対象として開く。ダメージ計算では選択したテンプレートを現在の計算条件へ展開し、以後の変更を `saved`、`modified`、`added`、`pending_remove` の差分として扱う。呼び出しただけではテンプレート本体を書き換えない。
